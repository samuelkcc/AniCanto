# 桌面／iPad 共用：配音、修復及原聲表演保護規格

規格識別：`anicanto-recovery-workflow-1`。本文件係 Mac、Windows 同 iPad build 對齊流程及驗收嘅交接入口；機器可讀摘要見 [RECOVERY-WORKFLOW-CONTRACT.json](RECOVERY-WORKFLOW-CONTRACT.json)。

**目前狀態：桌面 0.24.68 / build 221 已完成 Mac／Windows 打包並替換 dist；71 項相關測試、Mac 簽名／隔離啟動及兩平台包內容檢查通過。Windows 實機及 iPad 流程未由本輪驗收。** 「規格要求」不代表三平台已全部完成。平台實作、測試證據及剩餘差異必須分開記錄。桌面平台差異詳見 [DESKTOP-RECOVERY-PARITY.md](DESKTOP-RECOVERY-PARITY.md)。

## 1. 共用處理次序

1. 讀取指定來源音軌；保留原片及原裝字幕，記錄時間偏移。
2. 分離背景及人聲，檢查有效音訊、聲道、長度；不能只憑檔案存在當作完成。
3. 按原聲辨識及分句；字幕／OCR 只作意思、人名參考，不能代替原聲對白時鐘。
4. 準備每句／角色參考，翻譯至使用者所選目標語言；原稿、字幕及每種譯稿獨立保存。
5. 逐句生成；每句完成立即保存錄音、稿件、引擎、語言、參考及參數身分。
6. 依模式執行下列修復規則；完成嘅項目在恢復時沿用，不由頭重錄。
7. 保護原裝非語言表演，按原時間與已選配音／背景混音。
8. 輸出新版本並驗證音軌、字幕、可解碼性及長度；完成狀態同待人工校對分開。

## 2. 模式及重錄條件

| 規則 | 一般模式（預設） | 高速模式 | 詳細檢查（明確選用） |
| --- | --- | --- | --- |
| 保留首輪有聲錄音 | 是 | 是 | 原錄音仍保留歷史 |
| 語言／口音／同音字疑點 | 留報告，不因標記自行棄錄音 | 不做品質覆聽 | 可按額外證據有限修復 |
| 無聲／損壞 | 應用層最多兩次額外補聲嘗試，預算持久保存 | 不啟動品質重錄；必要有效音訊補救須有獨立明確預算 | 有限預算；不能重新進整批檢查 |
| 實際偏長 | 保留量測、合法空隙及有限保意改短；完整重讀後量度先採用 | 維持高速模式已明示嘅時長策略；不可偷偷啟動詳細改稿／覆聽 | 同一有界時長政策 |
| 原聲笑／喊／喘氣保護 | 保留 | 同樣保留，並非品質檢查 | 同樣保留 |
| 自動修復失敗 | 保留已完成檔案、顯示具體問題及可用操作 | 同左 | 同左 |

應用層補聲預算、引擎內部不完整解碼復原、時長改短預算必須各自記錄，不能以換階段／重新開啟程式重置額度。桌面一般模式偏長流程最多兩輪局部改短；多個候選稿同意思核對亦受各自有限預算約束。不能用文字長度直接認定錄音壞咗。

**有口音、辨識器標成日文／普通話、或者錯字，唔單獨等於真正錯語或漏字。** 一般模式保留有聲首輪，供人試聽；不得再因這些標籤反覆重錄。未確認證據標為 `unconfirmed`，不能偽裝 `passed`。人工改稿、已選錄音、保留原聲及受保護片段不能被自動覆蓋。

## 3. 非對白原聲表演：笑聲／喊聲優先

### 必須保護嘅內容

大笑、哭泣／抽泣、尖叫、喘氣、嘆氣等無需翻譯嘅原聲表演，優先保留原錄音，不要求 TTS 重新演繹。原片音樂、一般音效及 OP／ED 原聲繼續依既有保留設定處理。

### 共用判定次序

1. 分離後人聲亦包含笑聲／喊聲，不能丟棄整條人聲就當作背景已完整。
2. 取得有來源及時段嘅聲音事件證據；ASR 無文字只代表未辨識到，不能直接授權混回原片。
3. 以原聲可確認嘅實際字詞時間排除日文／其他原文對白，包含保護邊界。寬鬆整句時間無法確認時，保留不確定提示，唔猜笑聲位置。
4. 獨立非語言聲按原時間補返。碰到新生成配音延遲跨入時，僅局部壓低表演聲，不能因此全部刪除。
5. 同一演出已透過保留原片區間或個別 cue 補返時，不可再重複疊加。
6. 笑住講嘢／喊住講嘢等原文重疊，不能為救笑聲而重新帶入完整日文；無法安全抽取時明確列入校對。
7. 保存已保留事件、未安全保留事件、時間、原因、分類器／版本與窗口；提供原聲／分離／成品比較及人工保留入口。

### 分析時段與效能

演出事件嘅目標最終時間粒度為一秒窗口、半秒步進。**不是要求不加驗證就將任何分類模型輸入一律裁成一秒**：分類模型需要嘅上下文、填補及機率分佈可能不同，必須先用同一批正／負例量度。桌面 Windows 現有五秒分類與 Mac 一秒分類係已確認差異；0.24.68 已完成三條公開樣本嘅真正分類器對照：Windows 直接裁一秒會降低笑聲／哭聲信心並增加耗時，已否決；暫保留原分類器嘅五秒上下文。仍需以有時間定位能力嘅分類器或經驗證嘅上下文細分方案改善，唔可以只改數字宣稱兩邊一致。OP／ED 歌曲分類獨立處理，不可因本改動改其窗口或保護時間。

相同來源音訊、模型版本、分析設定嘅事件結果應跨語言／引擎重用。舊窗口結果不能偽裝成新時間粒度；音訊或模型變更應失效，不能用檔名相同代替內容驗證。短窗口會增加工作量，需列明時間成本及避免跨音軌重複推理。

## 4. 音訊品質及時間

- 原始生成率、分析率、最終交付率分清楚。16 kHz 分析檔只能作辨識／量測，不能用作最終演出或配音。
- 混回笑聲、保留原聲 cue、改時間及最終混音，不可無故將 Drama 3 44.1 kHz／GPT V4 48 kHz 降成24 kHz。按引擎交付規則處理；上採樣不代表低率聲音回復細節。
- 保持原聲表演時間，分段交界用短漸變；保留有效字句，不能以截尾充當時長修復。
- 背景及音效保留原有左右聲道資訊。配音聲道安排須明示，不可混淆分析 mono 與成品 stereo。
- 原裝字幕時間獨立保存；改配音時間不應連帶移動原裝字幕。

## 5. 保存、超時、暫停及報告

- 完成一條即原子保存一條；缓存身分包含音訊內容、模型／版本、相關設定及比較目標。
- 沒有完成嘅推理不能標成功；超時只停止本次所屬工作，不停止其他程式或 model service。
- 重新開始只做未完成項目；更換階段不可令同一錄音再次覆聽／重錄。
- 「暫停並保存」只暫停保存，不暗中匯出。已匯出版本不覆蓋；匯出狀態同待覆核分開。
- 完成報告須指出影片／語言／引擎／句子或時間、問題、已嘗試步驟、最後採用錄音，以及試聽／重錄／保留原聲等操作。

## 6. 三平台驗收表（iPad build 應逐項填寫實際結果）

| 驗收例 | 必須確認 |
| --- | --- |
| 第一輪有聲但ASR文字不同 | 一般模式不自動棄錄音／重錄；列不確定 |
| 無聲或損壞 | 限定額外補聲；重啟後預算不重置 |
| 量測偏長但有聲 | 仍可保意改短；完整新錄音適合時段先採用 |
| 獨立笑／喊／呼吸 | 一般與高速均保留原時間；不可變成空白 |
| 先笑後說日文／先說後喊 | 不連帶刪表演，亦不混回完整原文 |
| 原文與笑聲同時重疊 | 不冒稱可安全分離；留下明確人工校對 |
| 新配音延長到笑聲 | 有界壓低重疊部分，不刪整段笑聲 |
| 同一片多語言及多引擎 | 共用源事件證據，無重複疊加／反覆推理 |
| 音率及頻寬 | 用真FFmpeg／AVAudioEngine路徑確認；14 kHz訊號測試不能代替人耳品質驗收 |
| 暫停／超時／重啟 | 已完成錄音及逐句結果保留，沒有重新開始全批 |
| 手動改稿／採用錄音 | 自動修復不覆寫；匯出新版本可追溯 |

每邊記錄 app 版本、硬件、模型、模式、輸入片段 hash、處理時間、實際輸出、測試限制。模型可以因平台不同；共用修復判定及預算不能偷偷分叉。尚未完成嘅項目留 `pending`，不得因另一平台通過而標成通過。

## 7. 同步規則

改本流程時，同步更新本文件、機器可讀摘要、四語使用說明及對應測試，並在 版本交接紀錄 列出已做／待做。桌面與 iPad 各自保留實作及真機驗收紀錄。未經用戶授權，不覆寫正在轉換嘅程式、模型或專案；本文件本身不授權中斷其他工作。

### iPad build 實際接手步驟

1. 先讀本規格及 JSON 摘要，再把第 6 節每項對應到 iPad 實際實作位置；不能只搬桌面 UI 或沿用相同功能名稱。
2. 逐項記錄「現有行為 → 要求行為 → 改動檔案 → 測試輸入／輸出 → 結果」。保存、重試預算、偏長改短及非對白保護都要檢查。
3. 用同一測試片段分別跑一般／高速，測暫停後續跑；比較採用錄音、時間、混音及報告。模型差異另外註明，不用 ASR 字差代替人耳驗收。
4. 在交接紀錄填 app／規格版本及驗收證據；未完成填 pending。若需要改共同判定，先修訂此規格與摘要，再各自落實及驗證。

日後涉及偵測、翻譯、配音、修復、保護原聲或輸出行為嘅修正，都應按同一交接方法記錄；單純外觀更改可沿 UI 文件處理。
